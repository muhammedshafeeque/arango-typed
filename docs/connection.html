Connection Management

arango‑typed provides a Mongoose‑like connect() and a connection cache that reuses arangojs Database instances for identical connection parameters. It can also auto‑create the target database if it doesn't exist.

URI format (Mongoose‑like)

import { connect } from 'arango-typed';
await connect('http://localhost:8529/myapp', { username: 'root', password: '' });

Object formats

// Simplified
await connect({ url: 'http://localhost:8529', database: 'myapp', username: 'root', password: '' });

// Full (backward compatible)
await connect({ url: 'http://localhost:8529', databaseName: 'myapp', auth: { username: 'root', password: '' } });

Auto‑create database

When autoCreateDatabase is not set (or true), connect() will create databaseName automatically if the server returns "database not found".

await connect({ url: 'http://localhost:8529', database: 'appdb', username: 'root', password: '', autoCreateDatabase: true });

Connection reuse (cache)

Connections are cached by url|database|username. Subsequent connect() calls with the same triple reuse the existing instance after a quick version() check.

await connect('http://localhost:8529/appdb', { username: 'root', password: '' });
await connect('http://localhost:8529/appdb', { username: 'root', password: '' }); // reused

Helpers

  • getDatabase(): returns the default Database (throws if not connected).
  • getVectorSearch(), getGraphManager(), getTransactionManager(), getSearchManager(), getGeoQuery(), getBulkOperations(): convenience constructors bound to the default database.

Error handling

Connection errors throw ConnectionError with descriptive messages. If auto‑create fails, the message includes the inner error.

Options

  • url: string or string[] (cluster) for the server URL(s).
  • database / databaseName: database name.
  • username / password or auth: credentials.
  • agent: HTTP agent (keep‑alive, proxies).
  • arangoVersion: optional version hint for arangojs.
  • autoCreateDatabase: default true; set false to disable.
